# Health Vibe AI - مسار حذف الحساب والبيانات السريرية
**Account & Clinical Data Deletion Workflow (Right to Erasure & GDPR Compliance)**
*الإصدار:* `1.0.0` | *تاريخ السريان:* سبتمبر 2026

---

## 📌 1. الهدف والمبادئ الأساسية
تتيح منصة **Health Vibe AI** للمستخدمين (المرضى والأطباء) ممارسة حقهم في محو البيانات وحذف الحسابات الشخصية (`Right to Erasure / Right to be Forgotten`) بما يتوافق مع:
1. اللائحة العامة لحماية البيانات (GDPR - Article 17).
2. معايير أمان السجلات الصحية (HIPAA Security Rule).
3. المتطلبات التنظيمية الطبية للاحتفاظ بالسجلات السريرية المعتمدة (`Clinical Audit & Retention Guidelines`).

## 🔄 2. دورة حياة ومراحل مسار الحذف (Deletion Lifecycle)

```
[ المستخدم يطلب الحذف من الملف الشخصي ]
                   │
                   ▼
       [ نافذة التأكيد المضاعف ]
 (شرح الآثار + كتابة كلمة DELETE / حذف)
                   │
                   ▼
    [ التحقق الأمني من الجلسة حديثاً ]
 (Firebase Auth: Recent Login Check)
                   │
       ┌───────────┴───────────┐
       ▼                       ▼
(الجلسة قديمة)             (الجلسة صالحة)
إعادة تسجيل الدخول           تنفيذ الحذف الآلي
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ 1. مسح / حجب هوية الحالات السريرية (Cases Anonymization) │
│ 2. حذف طلبات توثيق الأطباء ومستندات Storage            │
│ 3. حذف ملف المستخدم من قاعدة البيانات (users/{uid})     │
│ 4. تسجيل حدث تدقيق غير محدد الهوية (Audit Log)         │
│ 5. حذف حساب المستخدم من Firebase Authentication        │
│ 6. تطهير البيانات المحلية والموافقات (LocalStorage)    │
└────────────────────────────────────────────────────────┘
                   │
                   ▼
    [ تسجيل الخروج والتحويل للشاشة الرئيسية ]
```

## 🛡️ 3. سياسة الاحتفاظ القانونية بالسجلات الطبية (Legal Retention Policy)

وفقاً للقوانين الطبية ولوائح حماية البيانات، لا يمكن حذف السجلات الطبية التي تم اعتمادها وتشخيصها سريرياً من قبل طبيب بشري بالكامل فوراً لأنها تخضع لفترات حفظ إلزامية قانونية (`Statutory Medical Record Retention`). يتبع النظام الاستراتيجية المتوافقة التالية:

| نوع البيانات | المدة القانونية | الأساس القانوني والتنظيمي | إجراء المعالجة والحذف |
| :--- | :--- | :--- | :--- |
| **بيانات الحساب المباشرة (PII)** | **0 أيام** (فوري) | GDPR Art. 17 / Right to be Forgotten | **حذف فوري ونهائي** من Firebase Auth وقاعدة `users/{uid}` والجلسات النشطة. |
| **المسودات والتقييمات غير المعتمدة** | **0 أيام** (فوري) | GDPR Principle of Data Minimization | **حذف فوري وكامل** من وثائق `cases/{caseId}`. |
| **السجلات الطبية المعتمدة سريرياً** | **5 سنوات** | قانون تنظيم مهنة الطب، آداب المهنة، و GDPR Art. 17(3)(b) | **حجب وتجريد الهوية بالكامل (Anonymization)**: استبدال الاسم بـ `Deleted Patient` وإلغاء الربط بالمريض مع الاحتفاظ بالقيم الحيوية الصرفة فقط لسجل التدقيق السريري الطبي والمسؤولية المهنية. |
| **سجلات التدقيق الأمني والنظام** | **6 سنوات** | HIPAA Security Rule 45 CFR § 164.316(b)(2)(i) | **أرشفة مشفرة وغير قابلة للتعديل** بدون معرّفات شخصية مباشرة لأغراض الامتثال الرقابي. |
| **النسخ الاحتياطية السحابية** | **30 يوماً** | Disaster Recovery & Backup Lifecycle | **تدوير وتطهير آلي دوري** مع تفعيل شواهد الحذف المشفرة (`Tombstone Suppression`) لمنع استعادة أي بيانات محذوفة. |
| **موافقات الجهاز والجلسات المحلية** | **0 أيام** (فوري) | Local Device Hygiene | **تطهير فوري** لكافة مفاتيح التخزين `localStorage` وجلسات المصادقة. |

## 💻 4. الواجهات البرمجية ونقاط النهاية (API Specification)

### 1. الاستعلام عن سياسة الاحتفاظ القانونية:
* **المسار:** `GET /api/user/privacy/retention-policy`
* **الوصول:** عام وموثق (Public / Authenticated).
* **المخرجات:** تفاصيل مدد الاحتفاظ (5 سنوات للسريري، 6 سنوات للأمني، 30 يوماً للنسخ)، المواد القانونية (GDPR 17(3)(b), HIPAA 164.316)، وحقوق المريض.

### 2. مسار حذف الحساب والبيانات:
* **المسار:** `POST /api/user/delete-account`
* **المصادقة:** إجبارية (`Authorization: Bearer <ID_TOKEN>`).
* **شروط الحماية:**
  * منع حذف حساب مالك النظام الأساسي (`OWNER_EMAIL`).
  * فحص حداثة تسجيل الدخول (`Recent Authentication Check <= 15 minutes`).
  * استخدام معاملات متزامنة (`Firestore Batch`) لمنع بقاء بيانات يتيمة.
  * تسجيل حدث التدقيق `ACCOUNT_DELETED` مع قناع أمني للبريد (`u***@domain.com`).

### 3. إعادة المحاولة الآمنة في حال التعثر الجزئي:
* **المسار:** `POST /api/user/privacy/retry-deletion`
* **الوظيفة:** استئناف الحذف من الخطوة التي تعثرت دون تكرار أو حذف خاطئ.

## 📥 5. مسار المريض داخل إعدادات الحساب (Patient Settings Workflow)

1. **الوصول للإعدادات:**
   - الدخول إلى لوحة المريض / الملف الشخصي (`#accountDeletionCard`).
   - عرض ملخص بارز لـ **سياسة الاحتفاظ القانونية (Legal Retention Policy)** ويوضح الـ 5 سنوات لحجب هوية السجلات والـ 6 سنوات لتدقيق HIPAA.
2. **تصدير البيانات قبل الحذف (Data Portability):**
   - زر `📥 تصدير بياناتي الطبية (JSON)` يتيح تنزيل أرشيف معتمد وموقع بـ SHA-256 قبل الحذف.
3. **عرض سياسة الاحتفاظ التفصيلية:**
   - زر `📜 سياسة الاحتفاظ القانونية` يفتح نافذة `#retentionPolicyModal` بجدول المواد القانونية.
4. **نافذة تأكيد الحذف المضاعف (`#deleteAccountModal`):**
   - تنبيه نهائي وتوضيح الآثار السريرية والقانونية.
   - زر تنزيل احتياطي سريع للبيانات.
   - تحدي كتابة كلمة `DELETE` أو `حذف`.
   - إدخال كلمة المرور للتحقق الأمني من الهوية.
   - مؤشر لحظي لمراحل الحذف والتعقيم السحابي.
