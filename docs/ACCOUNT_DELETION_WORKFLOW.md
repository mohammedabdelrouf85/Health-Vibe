# Health Vibe AI - مسار حذف الحساب والبيانات السريرية
**Account & Clinical Data Deletion Workflow (Right to Erasure & GDPR Compliance)**
*الإصدار:* `1.0.0` | *تاريخ السريان:* سبتمبر 2026

---

## 📌 1. الهدف والمبادئ الأساسية
تتيح منصة **Health Vibe AI** للمستخدمين (المرضى والأطباء) ممارسة حقهم في محو البيانات وحذف الحسابات الشخصية (`Right to Erasure / Right to be Forgotten`) بما يتوافق مع:
1. اللائحة العامة لحماية البيانات (GDPR - Article 17).
2. معايير أمان السجلات الصحية (HIPAA Security Rule).
3. المتطلبات التنظيمية الطبية للاحتفاظ بالسجلات السريرية المعتمدة (`Clinical Audit & Retention Guidelines`).

---

## 🔄 2. دورة حياة ومراحل مسار الحذف (Deletion Lifecycle)

```
[ المستخدم يطلب الحذف من الملف الشخصي ]
                   │
                   ▼
       [ نافذة التأكيد المضاعف ]
 (شرح الآثار + كتابة كلمة DELETE / حذف)
                   │
                   ▼
    [ التحقق الأمني من الجلسة حديثاً ]
 (Firebase Auth: Recent Login Check)
                   │
       ┌───────────┴───────────┐
       ▼                       ▼
(الجلسة قديمة)             (الجلسة صالحة)
إعادة تسجيل الدخول           تنفيذ الحذف الآلي
                   │
                   ▼
┌────────────────────────────────────────────────────────┐
│ 1. مسح / حجب هوية الحالات السريرية (Cases Anonymization) │
│ 2. حذف طلبات توثيق الأطباء ومستندات Storage            │
│ 3. حذف ملف المستخدم من قاعدة البيانات (users/{uid})     │
│ 4. تسجيل حدث تدقيق غير محدد الهوية (Audit Log)         │
│ 5. حذف حساب المستخدم من Firebase Authentication        │
│ 6. تطهير البيانات المحلية والموافقات (LocalStorage)    │
└────────────────────────────────────────────────────────┘
                   │
                   ▼
    [ تسجيل الخروج والتحويل للشاشة الرئيسية ]
```

## 🛡️ 3. معالجة البيانات الطبية vs البيانات الشخصية (PII vs Medical Audit)

وفقاً للقوانين الطبية، لا يمكن حذف السجلات الطبية التي تم اعتمادها وتشخيصها سريرياً من قبل طبيب بشري بالكامل فوراً إذا كانت تخضع لفترات حفظ إلزامية قانونية. لذلك يتبع النظام استراتيجية مزدوجة ذكية:

| نوع البيانات | حالة الفحص | إجراء الحذف |
| :--- | :--- | :--- |
| **بيانات الحساب الشخصية (PII)** | دائماً | **حذف فوري ونهائي** من Firebase Auth وقاعدة `users/{uid}`. |
| **طلبات الأطباء ومستندات الترخيص** | دائماً | **حذف فوري وكامل** من `doctor_applications` و Cloud Storage. |
| **تقييمات معلقة (Pending Cases)** | لم تُعتمد بعد | **حذف فوري وكامل** من وثائق `cases/{caseId}`. |
| **تقارير معتمدة (Approved Cases)** | معتمدة سريرياً | **إخفاء ومسح الهوية بالكامل (Anonymization)**: استبدال الاسم والبريد الإلكتروني بـ `Deleted Patient` وإلغاء الربط بالمستخدم مع الاحتفاظ بالقيم الحيوية الصرفة فقط لسجل التدقيق الطبي. |
| **موافقات الجهاز (LocalStorage)** | محلياً | **تطهير فوري** لكافة مفاتيح `hv_privacy_consent_*`. |

## 💻 4. الواجهات البرمجية ونقاط النهاية (API Specification)

### مسار الخادم الموثق:
* **المسار:** `POST /api/user/delete-account`
* **المصادقة:** إجبارية (`Authorization: Bearer <ID_TOKEN>`).
* **شروط الحماية:**
  * منع حذف حساب مالك النظام الأساسي (`OWNER_EMAIL`).
  * استخدام معاملات متزامنة (`Firestore Batch / Transaction`) لضمان عدم بقاء بيانات يتيمة.
  * تسجيل حدث التدقيق `ACCOUNT_DELETED` مع قناع أمني للبريد (`u***@domain.com`).

## 📥 5. ميزة تصدير البيانات قبل الحذف (Data Portability)
يوفر النظام للمريض زراً مباشراً:
`📥 تصدير بياناتي (JSON)`
يقوم بتجميع بيانات الملف الطبي وسجل القياسات والموافقات وتنزيلها بصيغة ملف `healthvibe-medical-data.json` قبل اتخاذ قرار الحذف النهائي.
